# Windows 安装、升级与恢复

当前交付为 **1.0.0-beta.1 测试版**，在 GitHub 标记为 Pre-release。安装包为 Windows x64 当前用户安装，未签名，不附带 CLI 或模型；不请求管理员权限，不自动启动真实任务。Windows 可能显示未签名提示，请先从项目 Releases 下载，并核对同一发布中的 `SHA256SUMS.txt`。

## 安装与启动

运行下载的 `Agent-Nexus-Setup-1.0.0-beta.1.exe`。安装结束后从开始菜单启动 Agent Nexus。程序不会自动在桌面创建快捷方式。源码开发者也可运行构建生成的 `release/win-unpacked/Agent Nexus.exe`，需保留整个目录；不要把 unpacked EXE 当作独立单文件程序。

测试版沿用已在本机验证的自用候选版功能。自用候选版已验证覆盖升级、实际用户库 v3→v7、升级前备份一致性、项目/任务保留、Codex 连接及重启无重放；beta 包的验证范围另见 [发布说明](RELEASE_1_0_BETA.md)。卸载现场流程未运行。Codex 会优先查 PATH，再查本机 OpenAI/Codex 原生安装目录，不要求手工修改 PATH。首次使用先导入一个本地项目，然后在设置查看本机 Provider 的真实能力和登录状态。缺失的 Provider 保留受限状态，不静默安装或替换成 Mock。

Codex / DSH 需使用各自已安装的原生程序和登录；WorkBuddy 本地桥接需在 Nexus 启用项目并复制 MCP 配置，再由用户在 WorkBuddy 中添加、首次信任并手动发送启动提示；Nexus 重启后需要在原生 MCP 列表刷新连接器。Model Hub 为可选项，本地和外部服务均由用户显式配置。外部模型的上下文流向须在 Run 中确认，Token 仅显示可信返回值，费用未知。

## 第一个工作流

1. 选择项目，进入「工作流」，选择模板或新建草案，填写名称、总体目标。
2. 编辑节点标题、指令、Worker、验收标准和依赖。连线表示源节点须先通过审查；也可用键盘操作下方依赖复选框。环形依赖会拒绝。
3. 模板默认只读。编码需要改文件时，将对应节点选为 Codex 并勾选节点写入；之后还须在 Leader 配置单独勾选项目写入，项目必须满足既有 Git / Worktree 条件。
4. 「保存工作流」只保存草案。未保存编辑可在当前进程切页/切项目后继续；退出应用前仍应保存。图上拖动位置只在当前编辑器保留，不随草案持久化。
5. 点击「载入 Leader 配置」，确认 Leader、Worker、Reviewer、推理来源和权限，再创建待批准计划。这一步不调用规划模型，也不会派发 Worker。
6. 核对 Run 的节点与权限。需要更改时点击「编辑待批准计划」，保存将产生新 revision 并使旧审批失效。点击「确认并批准此计划」才开始执行。已批准的运行计划禁止编辑。
7. 任务历史可搜索目标与全部持久化事件。监视器按顺序分页，支持回放与完整单事件详情；非空日志搜索是快照，再点「查找」刷新。回放只是查看记录，不重新执行任务。

Alt + 1–9 切换页面；Ctrl + Shift + M 切换监视器。输入框中不触发这组快捷键。

## 本地记录与升级

默认数据目录由 Electron 按应用名在当前用户 AppData 下管理；开发/测试可用 `NEXUS_DATA_DIR` 指向隔离目录。不要把 `.runtime`、`test-results`、SQLite 和凭证文件上传到公开仓库。

SQLite v7 在原有数据上新增工作流草案表。第一次从旧版本升级前，程序在数据库同目录保存 `nexus.sqlite.before-v7.bak` 原始副本（已存在则不覆盖）。M1–M4 的项目、设置、任务、计划和模型配置保留。旧版程序会拒绝 v7 数据库，不能直接交给旧版使用。

重启将未知执行收敛为 interrupted，不自动重新运行。先核查原生任务，再按界面要求恢复安全检查点。不要把“回放历史”或“打开程序”当作继续任务。

如需回退：先完全退出应用并核查在途原生任务；另存当前整个数据目录，再用升级前副本恢复数据库，并运行对应旧版本。升级后新增草案/任务不在升级前副本中。凭证依赖原 Windows 用户及系统加密环境，恢复后若解密失败，需重新配置；不要用明文替代凭证文件。

卸载配置保留用户数据。删除项目记录也不会删除原项目目录。需要彻底清理时，先自行备份并核对目录；程序没有提供自动不可恢复清理。

## 故障排查

- 保存版本冲突：另一编辑已保存新版本；先保留当前输入，再明确载入最新草案后重新修改。
- 写入或路径被拒绝：检查节点 Worker、Run 的单独写入授权、Git 根目录以及项目相对路径；不能通过指令文本扩权。
- 计划/步骤超时：Run 与步骤继续沿用既有时间上限，长时间编辑后须核查 Run 状态；不无限自动重试。
- Model Hub / Provider 不可用：检查所选端点、模型、原生登录和设置中的能力检测；不会伪造完成。
- 需要提供诊断：任务历史的「导出脱敏诊断」通过系统保存框输出本地 JSON，仅含版本、记录计数和中断计数，排除目标、日志正文、路径、凭证和模型响应。更详细资料须用户自行核查后分享。

安装配置依据 [electron-builder NSIS 文档](https://www.electron.build/docs/nsis/)，本次构建显式 `--publish never`，无更新服务器或自动上传。
